# Quiz Multiplayer Web App

배포주소:https://quiz-app-inky-ten-98.vercel.app/
* Render 무료 플랜이어서 온라인 방 만들때 로딩이 오래 걸릴수 있습니다.
* 서버가 켜질때 까지 10초에서 많게는 1분 이상 걸릴 수 있습니다.

## 만든 이유
로그인 기반 프로젝트(JWT, OAuth)는 각각 구현해본 경험이 있었지만,
실시간으로 상태가 변화하는 온라인 프로젝트는 아직 제대로 다뤄본 적이 없었습니다.

특히 여러 사용자가 동시에 같은 공간에 접속하고,
각 플레이어의 행동에 따라 게임 상태가 실시간으로 변경되는 구조를 직접 설계해보고 싶었습니다.

프로젝트 주제를 퀴즈 형태로 선택한 이유는 단순 CRUD보다:

- 상태 흐름 제어
- 타이머 처리
- 점수 계산
- 실시간 게임 진행
- 사용자 상호작용

등 다양한 로직을 직접 구현할 수 있었고,
직접 문제를 제작하는 과정 자체도 개발 공부에 도움이 될 것이라고 생각했기 때문입니다.


## Problem

- 일단 온라인 관련 서버를 개설해야하는 프로젝트를 해본 경험이 없기 때문에 서버 관련 정보를 모으는게 첫 번째 라고 생각했습니다.
그리고 각 온라인 방마다 유저들이 쾌적하게 움직일 수 있도록 설계하는게 관건이라고 생각했습니다.
- 두 번째는 어떤 문제 위주를 낼 것인가에 대한 퀴즈 방향 설계 문제인데 이건 처음부터 개발 공부를 겸행하기 위한 것이기 때문에 제가 생각한 내용이 있어 피그마로 구조를 잡아 쉽게 해결할 수 있었습니다.
- 세 번째는 온라인 방을 만들 때 각 방마다 개별적인 시스템을 두어야 한다는 것이었습니다.
어떤 방은 이미 시작한 방이고 각 유저가 정답을 누르는 타이밍도 다 다르기 때문에 각 유저와 방의 상태를 관리하며 모든 상태가 동일할때 다음 단계로 넘어가도록 설계하였습니다.
- 네 번째는 유저가 직접 퀴즈를 만들수 있게 하여 문제의 다양성을 높이고 게임의 재미를 늘릴 수 있게 경쟁구도로 설계하는 것입니다.

## Approach

프로젝트는 React + TypeScript 기반으로 제작했으며,
온라인 게임의 흐름을 상태 중심으로 설계하는 방향으로 개발했습니다.
온라인 실시간 서버는 node.js, socket.IO 을 사용했습니다. 

### 핵심 설계 방향

- 혼자서 할 수 있는 퀴즈 상태 관리 구조 설계
- 개인 퀴즈 상태 관리에 기반한 온라인 방 설계
- 각 온라인 방 기반 상태 관리 구조 설계
- 게임 상태를 status 기반으로 분리
- 컴포넌트 역할 분리
- 실제 온라인 환경을 고려한 구조 설계
- 서버 연결 (socket.IO)

게임 흐름 대부분이 room 상태를 기준으로 동작하도록 설계했습니다.

## Action

### 시작
우선 개인용 퀴즈 게임으로 목표를 잡고 밑작업을 하였습니다.
유저가 원하는 문제집을 선택해 문제를 풀고 그 결과를 보여주는 것 이 첫번째 최종 목표입니다.

### 퀴즈 세팅
우선 더미 퀴즈셋을 만들었습니다.
구조는 간단하게
```
export type Question = {
  id: number;
  question: string;
  choices: string[];
  answerIndex: number;
};
export type QuizSet = {
  id: string;
  title: string;
  category: string;
  questions: Question[];
};
```
로 잡았습니다.
나중에 유저가 직접 만드는 기능을 넣을때 author 속성만 더 추가하면 되게 설계하였습니다.
Question은 각 퀴즈별 세팅이고 QuizSet은 문제집 전체입니다.

### 퀴즈 상태 관리 함수 추가
일단은 개인용이니 퀴즈를 풀때 상태를 useState에 담아 관리하였습니다.

### 유저 정보 추가
기획했을때부터 무거운 로그인 방식은 이미 전 프로젝트들에 했기 때문에 가볍게 만들고 싶었습니다.
그래서 간단하게 닉네임만 입력하면 유저 정보가 로컬스토리지에 들어오게 설계하였습니다.
```
export type Player = {
  id: string;
  nickname: string;
  score: number;
  answeredQuestionIndex?: number | undefined;
  isLastAnswerCorrect?: boolean | undefined;
};
```
유저가 답을 고르면 isAnswerChecked 가 true로 변경되며 다음문제로 넘어가고 유저가 선택한 데이터를 받아와 정답과 오답을 체크해주며 동시에 점수를 올리는 방식으로 설계하였습니다.
또한 닉네임 중복을 허용하고 본인 닉네임 옆에 (나) 를 붙여 구분하도록 하였습니다.
그리고 유저가 만든 문제집은 닉네임 기준이 아닌 플레이어ID기준으로 설계하였습니다.
나중에 온라인 기능을 만들때 방장 여부 정도만 추가해주면 될거같습니다.

### 본격적인 Room 세팅
개인용 퀴즈를 끝냈으니 이를 기반으로 온라인 방에 필요한 타입들을 추가해주었습니다.
일단 mock 용으로
```
export type Room = {
  id: string;
  title: string;
  quizSetId: string;
  quizSetTitle: string;
  hostNickname: string;
  Players: Player[]
  maxPlayers: number;
  status: "waiting" | "playing" | "finished" | "countdown" | "result";
};
```
방에 필수요건부터 채워주었습니다.
그리고 서버를 구축하기 전에 방을 들어가면 방이 생성되는 함수, 게임 시작시 상태를 관리해주는 함수 등을 만들어줬습니다.

waiting
→ countdown
→ playing
→ result
→ playing
→ finished

이를 통해:

- 시작 카운트다운
- 문제 결과 대기
- 다음 문제 전환
- 게임 종료 처리

등을 안정적으로 구현할 수 있었습니다.

### 온라인 방 시스템 구현
기본적인 서버 붙이기 전 코드 구현을 다 끝낸 후 본격적인 서버를 붙이고 기존 함수들을 소켓에 연결하였습니다.
기존 함수들에 soket.emit 를 넣고 기존 함수들을 서버 io에 연결하였습니다.

- Socket.IO 기반 실시간 통신 시스템 구현
- 서버 메모리 기반으로 온라인 방(Room) 상태 관리
- 소켓 서버 연결 시 실시간 방 생성 및 유저 입장/퇴장 동기화
- 최대 인원 제한 처리
- 게임 진행 중 입장 제한
- 방장 자동 위임 기능
- 실시간 게임 흐름 채팅창에 알림
- 한번에 여러 요청이 들어갈 수 있으므로 각각 방어코드 구현

등 여러 실시간 서비스를 안정적으로 처리될 수 있도록 설계하였습니다.

### 제한 시간 및 진행 바 구현

문제별 제한 시간을 두고,
남은 시간에 따라 진행 바가 자연스럽게 감소하도록 구현했습니다.

답변 중복 제출 방지

UI와 로직 양쪽에서 중복 제출을 방지했습니다.

또한 버튼 disabled 상태를 함께 적용해 UX를 개선했습니다.

채팅 및 시스템 메시지 구현

플레이어 채팅뿐 아니라:

- 입장
- 퇴장
- 방장 변경
- 게임 시작

등을 시스템 메시지로 자동 출력하도록 구현했습니다.

### 사용자 확장성

- message
- 사용자 정의 문제집 기능 구현(user의 id를 구분하여 본인만 삭제 수정 가능하게 설정, supabase에 저장)
- 문제집 생성
- 수정 / 삭제
- 카테고리 분류
- playerid localStorage 저장 (다음 접속시 자동 로그인)
- 문제집이 삭제/수정 될때 실시간으로 업데이트

기능을 구현해 사용자 확장성을 높였습니다.

프로젝트를 통해 단순 UI 구현을 넘어서,
상태 기반 게임 로직 설계 경험을 얻을 수 있었습니다.

특히 다음 부분에서 큰 성장을 경험했습니다.

- 상태 관리 구조 설계
- room 상태 중심 설계
- 게임 상태 분리
- 타이머 흐름 관리
- 컴포넌트 역할 분리
- React 로직 처리 경험
- useEffect 기반 타이머 처리
- 상태 변경 타이밍 제어
- 렌더링 흐름 이해
- 상태 업데이트 충돌 디버깅 경험
- 사용자 경험 개선
- 카운트다운 연출
- 문제 전환 템포 조절
- 진행 상태 시각화
- 채팅 및 시스템 메시지 처리
- server와 client의 분리
- server에서 요청을 보내 room, player 상태 관리 처리
- 실시간 온라인 프로젝트 배포

등을 통해 단순 기능 구현이 아닌 실제 게임 같은 흐름을 만드는 경험을 할 수 있었습니다.
